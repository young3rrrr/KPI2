    - **Огляд результатів**:
        - **Позитивно**:
            1. Побудовано компонентну діаграму UML 2 у PlantUML із чіткими межами системи OpenCRM та 5 внутрішніми шарами.
            2. Використано нотацію provided та required інтерфейсів (куля-гніздо) між компонентами.
            3. Зовнішній поштовий шлюз External SMTP Gateway винесено за межі системи (платіжні шлюзи та телефонія відсутні згідно з Out of Scope Лаб 2).
            4. Згенеровано читабельні рендери .svg та .png.
        - **Негативно**:
            1. **Порушення ізоляції PricingService (розбіжність із Лаб 3):** на діаграмі DealController напряму викликає IPricingService, а сам PricingService напряму звертається до IDealRepository. За діаграмами послідовності Лабораторної 3 (SC-01, SC-02) та ADR-0003 PricingService є суто обчислювальним сервісом без доступу до БД, якого викликає тільки DealService.
            2. **Обхід сервісного шару контролером каталогу:** CatalogController звертається напряму до репозиторію IProductRepository, минаючи шар бізнес-логіки. Для керування товарами (UC-03) і перевірки прав Admin має використовуватися окремий CatalogService.
            3. **Відсутність компонента безпеки та Rate Limiting (розбіжність із NFR Лаб 2):** у вхідному шарі API немає модуля Auth & RateLimit Middleware, який відповідає за перевірку JWT токенів, ролей SalesManager/Admin (NFR-04) та відсікання навантаження понад 80 RPS зі статусом HTTP 429 (NFR-02).

    - **Необхідні зміни для Ітерації 2**:
        1. Прибрати в spec.md прямі звʼязки між DealController і PricingService та між PricingService і DealRepository (залишити виклик PricingService виключно з боку DealService).
        2. Додати в сервісний шар spec.md компонент CatalogService між CatalogController та ProductRepository.
        3. Додати у вхідний шар API компонент Auth & RateLimit Middleware для трасування вимог NFR-02 та NFR-04 із Лабораторної 2.
