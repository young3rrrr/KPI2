# 1. Внутрішні компоненти системи OpenCRM

1. **Клієнтський веб-інтерфейс(Web UI - React / Ant Design)** - Фронтенд частина системи для менеджерів з продажу (SalesManager) та адміністратора (Admin).
    * Призначення: відображення воронки угод (Kanban), карток лідів і клієнтів, каталогу товарів та списку активностей.
2. **Вхідний шар API(API Gateway & Controllers - Fastify)** - Шар обробки HTTP запитів по HTTPS (TLS 1.3).
    * Склад: DealController (маршрути угод і знижок), LeadClientController (робота з лідами та клієнтами), CatalogController (керування товарами для Admin), ActivityController (задачі менеджера).
3. **Сервісний шар бізнес-логіки(Business Services)** - Основне ядро правил системи.
    * DealService: управління життєвим циклом угоди (UC-01, UC-05) та перевірка статусів.
    * PricingService: розрахунок вартості позицій DealItem та пропорційний перерахунок персональної знижки (UC-06).
    * LeadClientService: кваліфікація та конвертація ліда в клієнта 1:1 (UC-02).
    * ActivityService: створення та контроль виконання завдань менеджера (UC-04).
    * EmailService: внутрішній модуль формування сповіщень про договори.
4. **Шар доступу до даних(Data Access Layer - Drizzle ORM)** - Репозиторії для роботи з базою даних.
    * DealRepository (таблиці Deal та DealItem), ProductRepository (таблиця Product), ClientLeadRepository (таблиці Lead та Client), ActivityUserRepository (таблиці Activity та User).
5. **База даних(PostgreSQL 16+)** - Реляційне сховище даних для всіх 7 сутностей із Лабораторної 1.

# 2. Межі системи та зовнішні інтеграції

1. **Межа системи(OpenCRM System Boundary)** - Охоплює Web UI, Fastify API, сервісний шар, репозиторії та локальну БД PostgreSQL у контейнері.
2. **Зовнішній поштовий шлюз(External SMTP Gateway)** - Єдина зовнішня система за межами OpenCRM, через яку EmailService відправляє клієнтам листи з договорами.

# 3. Інтерфейси та залежності між компонентами.

1. Взаємодія клієнта та API.
* Web UI звертається до контролерів Fastify через REST API інтерфейс.

2. Взаємодія контролерів та сервісів.
* DealController викликає методи DealService та PricingService для оформлення угоди і розрахунку знижки.
* Інші контролери звертаються до відповідних сервісів (LeadClientService, ActivityService, ProductRepository).

3. Взаємодія сервісів, репозиторіїв та зовнішньої пошти.
* Сервіси бізнес-логіки звертаються до репозиторіїв Data Access Layer для читання та збереження сутностей у PostgreSQL.
* EmailService передає сформоване повідомлення до зовнішнього поштового шлюзу External SMTP Gateway.

# 4. Критерії прийняття для компонентної діаграми (Acceptance Criteria)

1. **AC-01 (Нотація та валідність)**:
    * Архітектура системи має бути описана декларативним кодом PlantUML (component diagram) у файлі lab5/model/component-diagram.puml без помилок рендерингу.
2. **AC-02 (Повнота шарів та межі системи)**:
    * На діаграмі мають бути чітко виділені межі системи OpenCRM, всі внутрішні шари (UI, API, Services, Repositories, Database) та зовнішній поштовий шлюз поза межами системи.
3. **AC-03 (Інтерфейси та залежності)**:
    * Між компонентами повинні бути показані provided та required інтерфейси і напрямки залежностей.
4. **AC-04 (Трасування до Лабораторних 1–4)**:
    * Всі компоненти повинні відповідати сутностям з Лабораторної 1, вимогам з Лабораторної 2 та учасникам взаємодії з Лабораторних 3 і 4.
